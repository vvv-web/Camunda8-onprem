# Готово к тесту руководителем

## Цель

Подготовлено on-prem решение `Camunda 8` для сотрудников модуля «Цифровизация проектных задач УЭ»:

- систематизация, анализ и хранение бизнес-процессов
- визуализация процессов
- пользовательский доступ для команды

## Что уже выполнено

- Развернут стек `Camunda 8 Self-Managed` на корпоративном сервере `pop-os`
- Подняты сервисы: `Zeebe`, `Operate`, `Tasklist`, `Keycloak`, `Identity`, `Elasticsearch`, `Console`, `Optimize`, `Connectors`, `Web Modeler`, `Postgres`, `Mailpit`
- Настроен публичный пользовательский доступ через домен `https://camunda.acom-offer-desk.ru`
- Настроен `Keycloak admin` для создания пользователей: `https://camunda.acom-offer-desk.ru/auth/admin/`
- Настроен внутренний маршрут через `VPS -> Tailscale -> pop-os` без поломки других проектов на VPS
- Старый сценарий с `Tailscale` сохранен как резервный/служебный вариант
- Проверен логин в основные пользовательские UI
- Проведен базовый end-to-end (`E2E`) smoke test Camunda

## Что уже готово показать руководителю

Руководитель может проверить:

- открытие `Operate`
- открытие `Tasklist`
- вход пользователя в систему
- открытие `Keycloak admin`
- создание нового пользователя для коллег
- доступность системы через домен без установки `Tailscale`
- базовую работоспособность Camunda на простом BPMN-процессе

## Что проверено в E2E тесте

- выполнен деплой тестового BPMN-процесса `Start -> User Task -> End`
- успешно запущен инстанс процесса
- инстанс появился в `Operate`
- `user task` найдена через `Orchestration Cluster API`
- `REST API v2` ответил штатно
- подтвержден сценарий: Camunda принимает процесс, запускает его и отображает результат в пользовательском UI
- дополнительно пройден демонстрационный тест вложенных процессов: `Call Activity` и `Embedded Subprocess` успешно выполняются до состояния `COMPLETED`

## Лицензия и текущий режим

- На текущем этапе решение используется в режиме пилота / внедрения / тестирования без приобретенной коммерческой лицензии Camunda
- Для апробации, демонстрации и проверки сценариев систему можно использовать уже сейчас
- При переходе к постоянной рабочей эксплуатации отдела вопрос лицензии Camunda нужно будет formalизовать отдельно
- Для `Web Modeler` без лицензии действует ограничение до `5 concurrent users`

## Варианты моделирования

- `Desktop Modeler` — локальное приложение на ПК сотрудника; на текущем этапе это более простой и приоритетный вариант
- `Web Modeler` — браузерный вариант; потенциально удобен для команды, но требует отдельной приоритизации, проверки лицензии и схемы публикации
- Текущий практический приоритет: основной доступ сотрудников через `Operate` и `Tasklist`, моделирование в первую очередь через `Desktop Modeler`

## Что еще не закрыто полностью

- наполнение реальным иерархическим списком бизнес-процессов УЭ
- прикладная приемка сотрудниками отдела на реальных процессах
- финальное решение: использовать `Web Modeler` или `Desktop Modeler` как основной инструмент отрисовки BPMN для сотрудников

## Вывод

На текущем этапе решение развернуто, доступно и готово к демонстрации руководителю как рабочий on-prem стенд `Camunda 8` для команды.  
Следующий практический этап — загрузка и согласование реальных BPMN-процессов отдела.
